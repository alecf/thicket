# Near-miss duplication: L3, then maybe embeddings

## Goal

Exact hashing splits near-identical code into separate clusters. An inserted
optional field breaks L1 equality. So one template with 24 copies can appear as
a 19-copy finding and a 5-copy finding. Each piece ranks lower than the whole,
and a reader who acts on one leaves the other behind.

This plan groups near-identical fragments into one finding. It answers three
questions with measurements before it commits to an approach:

1. Does near-miss matching change which findings a reader sees?
2. Do embeddings find useful matches that a structural measure misses?
3. Which fragments are worth comparing at all?

## What already exists

- **PRD §5.3 specifies L3.** MinHash over 5-shingles of the normalized token
  stream, LSH banding for candidates, exact Jaccard to verify, union-find to
  group. It was deferred from v1 and never built.
- **`prototypes/ladder.mjs` implements L3** as a research script. On Sample A
  it added 175 clusters over 1,164 shapes.
- **`src/report/variants.ts` does a small version.** It compares the printed
  findings with each other by shingle Jaccard, at a measured threshold of 0.6.
  It names a near-copy. It never merges one.
- **PRD §11.4 cut embeddings.** The reason was recall: the report already has
  ten times more candidates than slots. This plan's motive is ranking, not
  recall. A fragmented cluster ranks below the whole it belongs to.

## Constraints

- **Determinism (AGENTS.md §1).** A float from an embedding model varies with
  hardware, runtime and quantization. A pair near a threshold would flip
  between machines. So no float decides cluster membership. A candidate source
  may propose a pair. An exact, integer-or-rational measure decides it.
- **The adapter seal (§2).** The only code that talks HTTP lives in one
  directory, the way the only code that talks to tsgo lives in `src/extract/`.
- **The cache (§5).** Anything cached must leave cold and warm cluster lists
  equal.
- **No inference engine in the binary (§7).** A model runs in a separate local
  server. Ollama, LM Studio, llama.cpp's server and vLLM all serve the
  OpenAI-compatible `/v1/embeddings` endpoint. thicket would be a client.
- **Fifth hazard.** A fragment beside its own ancestor scores about 0.99.
  Every similarity measure must exclude ancestor–descendant pairs.

## Phase 0: measure

A research script, `prototypes/near-miss.ts`, built on the real extraction
code. It reduces each repository to its distinct L1 shapes, then compares
three candidate sources on those shapes:

| Source | What it compares | Deterministic |
|---|---|---|
| MinHash + LSH | 5-shingles of the L2 token stream | yes |
| Integer n-gram cosine | feature-hashed counts of AST kind n-grams | yes, in integer arithmetic |
| Model embedding | source text of a representative, via Ollama | no |

For each source it reports how many pairs it proposes and how many shapes
those pairs unite. It also reports how many pairs it finds that the others
miss. The script prints counts and writes samples for judging.

**Judging.** Subagents rate sampled merges without being told which source
produced them, or what result is hoped for. Each judge sees two or three
copies and answers one question: would consolidating these into one
abstraction be worth doing? Samples mix all sources with controls drawn from
below the threshold, in a shuffled order.

**Gating.** The judged sample is broken down by node kind, size band and
literal share. A bucket whose merges judges rate as useless is a candidate for
skipping. A bucket is skipped only on that evidence.

**Repositories.** Two large public TypeScript monorepos (Sample C, 6,595
analyzed files, and Sample D, 2,509) and this repository. Committed text uses
only the anonymized names (AGENTS.md §6).

**Decision rules.**

- Build L3 if judged near-miss merges are mostly useful.
- Build an embedding source only if it finds judged-useful merges that
  MinHash at a looser threshold does not.

## Phase 1: L3 in the core

- `src/fingerprint/near.ts` exposes one function. It takes shaped fragments and
  returns L3 clusters. Candidate generation, verification and grouping stay
  inside it.
- `Level` gains `"L3"`. The ranker gains an L3 level weight and count
  exponent, set against judged findings.
- An L3 cluster absorbs exact clusters that it unites. It cross-references only
  within its own level.
- The cache stores what L3 needs per shape, and the cold/warm cluster test
  covers it.
- The report prints the similarity range for an L3 finding.
- `--no-near` turns it off (AGENTS.md §4b).
- Judges compare the top 40 with and without L3 on each sample.

## Phase 2: embeddings as an optional candidate source

Only if Phase 0 justifies it. Off by default. The model proposes pairs.
The Phase 1 verifier decides them. The model name joins the config hash.

## Out of scope

- Statement windows (issue #27). Whole-node matching cannot see a repeated
  run of statements inside a longer block, with or without embeddings.
